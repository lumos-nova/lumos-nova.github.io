CyclicBarrier

什么是 CyclicBarrier？

​CyclicBarrier​ 是 Java 并发包中提供的一个同步辅助类，用于协调多个线程的执行。它允许一组线程互相等待，直到所有线程都到达一个特定的屏障点（barrier point）后再继续执行。与 CountDownLatch​ 不同，CyclicBarrier 可以被重用，即当所有线程到达屏障点后，它可以被重置，再次用于等待下一次的线程集合。

CyclicBarrier 的主要功能

  • ​线程等待：所有参与的线程在某个操作完成后会阻塞，等待其他线程也完成该操作。
  • ​重置功能​：当所有线程通过屏障后，CyclicBarrier 可以被重置，继续用于下一轮的等待。
  • ​屏障动作​：可以指定一个屏障动作（Runnable），当所有线程到达屏障点后，该动作会被执行一次。

CyclicBarrier 的基本用法

import java.util.concurrent.CyclicBarrier;
public class CyclicBarrierExample {
    public static void main(String[] args) {
        int numberOfThreads = 3;
        CyclicBarrier barrier = new CyclicBarrier(numberOfThreads, () -> {
            System.out.println("所有线程已到达屏障点，执行屏障动作！");
        });
        for (int i = 0; i < numberOfThreads; i++) {
            new Thread(() -> {
                try {
                    System.out.println(Thread.currentThread().getName() + " 开始执行任务...");
                    // 模拟任务执行
                    Thread.sleep(1000);
                    System.out.println(Thread.currentThread().getName() + " 到达屏障点，等待其他线程...");
                    barrier.await();
                    System.out.println(Thread.currentThread().getName() + " 通过屏障点，继续执行后续操作。");
                } catch (Exception e) {
                    e.printStackTrace();
                }
            }).start();
        }
    }
}

CyclicBarrier 的关键方法

  • ​await()：使当前线程在屏障点等待，直到所有线程都到达该点。
  • ​reset()：重置屏障，使其可以再次被使用。
  • ​getNumberWaiting()：获取当前正在等待的线程数。
  • ​getParties()：获取参与屏障的线程总数。
  • ​getBroken()：检查屏障是否被打破（即是否有线程在等待时被中断或超时）。

CyclicBarrier 的常见使用场景

  1. ​多线程任务分段处理：例如，多个线程分别处理数据的不同部分，最后在屏障点汇总结果。
  2. ​并行计算任务：将一个大任务分解为多个子任务，每个子任务由一个线程处理，所有线程完成后执行后续操作。
  3. ​线程间通信：用于协调多个线程的执行顺序，确保它们在特定点同步。

示例场景：多线程并行计算

假设有 3 个线程分别对一组数据进行处理，处理完成后需要汇总结果。

import java.util.concurrent.CyclicBarrier;
public class CyclicBarrierParallelProcessing {
    public static void main(String[] args) {
        int numberOfThreads = 3;
        CyclicBarrier barrier = new CyclicBarrier(numberOfThreads, () -> {
            System.out.println("所有线程已完成计算，开始汇总结果。");
        });
        for (int i = 0; i < numberOfThreads; i++) {
            new Thread(() -> {
                try {
                    System.out.println(Thread.currentThread().getName() + " 开始处理数据...");
                    // 模拟数据处理
                    Thread.sleep(1000);
                    System.out.println(Thread.currentThread().getName() + " 数据处理完成，到达屏障点。");
                    barrier.await();
                    System.out.println(Thread.currentThread().getName() + " 汇总结果完成。");
                } catch (Exception e) {
                    e.printStackTrace();
                }
            }).start();
        }
    }
}

注意事项

  • ​异常处理​：如果某个线程在调用 await()​ 时被中断或超时，CyclicBarrier​ 会被标记为“打破”，之后所有等待的线程都将抛出 BrokenBarrierException。
  • ​线程安全​：CyclicBarrier 是线程安全的，适合在多线程环境中使用。
  • ​性能考量​：在某些情况下，使用 CyclicBarrier​ 可能不如使用 CountDownLatch​ 或 Semaphore 高效，需根据具体场景选择。

总结

​CyclicBarrier 是 Java 并发编程中一个非常实用的工具，特别适用于需要多个线程协同完成任务的场景。它不仅能实现线程间的同步，还支持重用和自定义的屏障动作，因此在并行计算、任务分段处理等场景中应用广泛。
