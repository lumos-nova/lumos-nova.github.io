Spark概述

Spark概述及主要组件

1. 大数据开发的总体架构

数据来源层

1、MySQL等结构化数据库
2、日志、json文件、xml文件等半结构化数据
3、视频、语音等非结构化数据
 		- 需要使用DataX、kettle、sqoop、flume、Kafka等数据传输工具将数据传入到数据仓库（HDFS）中

数据传输层（数据采集）

通过各种数据传输工具，将不同源的数据统一导入到HDFS中
     Sqoop：Apache下免费开源的采集框架。数据源是关系型数据库。
     DataX：阿里巴巴提供的开源免费的数据采集框架。用于离线采集。官网：https://github.com/alibaba/dataX
     Kettle：可视化的方式进行数据采集。数据源很多，可以是关系型数据库，也可以是其他。
     Flume：Apache下，专门采集日志的框架（JS埋点、Nginx访问日志），实时采集的框架
     Canal：阿里巴巴提供的开源免费数据采集框架。用于实时采集。https://github.com/alibaba/canal
     FlinkCDC：是阿里开源的数据采集框架，支持实时采集，可以采集增量和全量
     小结：采集在大数据的地位不重要，面试也不是核心点。

数据存储层

将大量数据存储起来，来满足数据的快速检索与统计
     HDFS:Hadoop Distributed File System（Hadoop分布式文件系统）。
     Hive:不存储数据。
     HBase:本质上也是把数据存储在HDFS上。
     Kafka:可以存储海量数据。不能永久存储，它属于消息队列，只是临时存储。
     ElasticSearch: ES，可以存储海量数据。用于搜索领域。
     对象存储（Object Storage）: OSS（阿里云）、MinIO（开源免费）、AWS（亚马逊对象存储，S3）存储空间利用率要高。

资源管理层

对分布式系统的资源进行统一管理
     Yarn: 专用的大数据 资源管理框架，通用资源管理系统，通常用于管理CPU、内存，不仅可以集成Hadoop还能集成Spark\Flink等大数据框架

数据计算层

该层主要是对HDFS上存储的大量数据，进行离线或实时计算
     离线计算引擎
         MapReduce: 第一代大数据计算框架，分而治之的思想。
         hive: 底层走的仍然是MR
         spark: 分布式内存迭代计算框架。
     实时计算引擎
         Spark: 分布式内存迭代计算框架。
         Flink:

任务调度层

对整个大数据系统，进行集中的任务调度
     Apache Oozie: 老的调度系统
     Crontab: Linux自带的调度系统
     Azkaban: 阿兹卡班，不是Apache的，非常好用。
     DolphinScheduler: DS，海豚调度系统

业务模型层

将经过处理后的数据，进行可视化展示以及业务逻辑处理
     FineReport
     Echarts

2. Spark的概念

Spark是一个快速通用的集群计算系统，分布式内存计算框架。
​​

四大特点

1. 快速: 运行速度快，基于内存迭代，减少数据落盘
2. 易用: 简单使用，且支持多种编程语言，如：Scala、Java、Python、R
3. 通用: 可以用于处理离线、实时、图计算、机器学习等各种大数据场景
4. 到处运行: 可以本地运行、独立模式运行、Yarn运行、mesos、k8s等

主要组件

Spark Core: Spark的核心模块，主要有一下两部分的功能
     1、负责任务调度、内存管理、错误恢复、与存储系统交互
     2、对RDD（弹性分布式数据集）的API定义
 Spark SQL: 用于结构化数据处理，提供了SQL查询接口
     1、可以使用SQL或hiveSQL来方便的查询数据
     2、支持将SQL融入Spark应用程序的开发过程中
 Spark Streaming: 对实时数据的流式计算组件
     1、将流式计算分解成一个个小批量处理的作业
     2、支持对实时数据流进行可伸缩、高吞吐量、高容错对的流处理
     3、提供了用来操作数据流
     4、通过将流数据按指定时间片累计未RDD，然后将每个RDD进行批处理，进而实现大规模的流数据处理
 MLlib: 机器学习库
 GraphX: 图(知识图谱)计算库

3. Spark任务执行流程

  1. 任务划分：Spark 将任务划分为多个 stages 和 tasks。每个 stage 包含多个 tasks，且每个 task 是对数据集中⼀个分区的计算。
  2. 任务调度：Spark 会将每个 stage 中的 tasks 分配给集群中的 Executor 进⾏计算。任务调度分为两个阶段：第⼀阶段为 Task Scheduler，在该阶段 Spark 会将任务分配给可⽤的 Executor；第⼆阶段为 DAG Scheduler，Spark 会在该阶段优化任务执⾏计划。
  3. 数据分区：Spark 将数据集划分为多个分区，每个分区会被分配到集群中的某⼀个 Executor 上进⾏计算。每个 Executor 会处理多个分区，且每个分区只会被⼀个 Executor 计算。
  4. 任务执⾏：Executor 会从 Driver 程序中获取任务信息，并根据任务信息从对应的数据分区中获取数据，然后执⾏具体的计算任务。
  5. 任务结果收集：Executor 执⾏完任务后，将计算结果返回给 Driver 程序。Driver 程序会收集所有 Executor 返回的计算结果，并进⾏汇总。
  6. 结果输出：最后，Driver 程序会将计算结果写⼊到外部存储系统（如 Hadoop HDFS 或者 Apache Cassandra）中。

在这个过程中，Spark 会利⽤⼀些优化技术来提⾼任务执⾏的效率，例如任务合并、数据本地化、缓存等。通过这些技术，Spark 可以在⼤规模数据处理和分析任务中实现⾼效的计算和快速的结果输出。

简单版

1、client提交任务，哪台服务器提交，哪台就是client 2、client向ResourceManager申请启动ApplicationMaster 3、RM收到请求后，找一台NodeManager来启动ApplicationMaster 4、被找到的NodeManager会在一个Container资源容器中启动ApplicationMaster，并在其中启动一个Driver进程 5、启动Driver后，会由ApplicationMaster向RsourceManager申请资源用于启动Executor 6、RM会返回一个NodeManager列表 7、ApplicationMaster会根据该列表在每个NodeManager的container中启动一个Executor 8、Executor会反向注册给Driver， 9、Driver会发送task给Executor，并监控task的执行，Executor执行任务，返回执行结果给Driver 10、Driver会回收结果，发送下一个task，直到所有任务完成 11、Driver会注销executor，同时向resourcemanager申请注销自己

2. YARN集群架构

2.1 Yarn基本架构

经典的主/从（Master/Slave）架构，主要由ResourceManager 、 NodeManager 、 ApplicationMaster 和Container等几个组件构成。
​​

  1. ResourceManager
  2. NodeManager
  3. ApplicationMaster
  4. Container
  5. Task

2.2 YARN的执行流程：

  1. 客户端提交应用程序（可以是MapReduce程序、Spark程序等）到ResourceManager。
  2. ResourceManager分配用于运行ApplicationMaster的Container，然后与NodeManager通信，要求它在该Container中启动ApplicationMaster。ApplicationMaster启动后，它将负责此应用程序的整个生命周期。
  3. ApplicationMaster向ResourceManager注册（注册后可以通过ResourceManager查看应用程序的运行状态）并请求运行应用程序各个Task所需的Container（资源请求是对一些Container的请求）， 如果符合条件，ResourceManager就会分配给ApplicationMaster所需的Container（表达为Container ID和主机名）。
  4. ApplicationMaster 请 求 NodeManager 使 用 这 些Container来运行应用程序的相应Task（将Task发布到指定的Container中运行）。
  5. 各个运行中的Task会通过RPC协议向ApplicationMaster汇报自己的状态和进度 ，这样一旦某个Task运行失败 ，ApplicationMaster就可以对其重新启动。当应用程序运行完成时，ApplicationMaster会向ResourceManager申请注销自己

1、客户端申请提交运行MR程序
 2、ResourceManager验证是否合法，如果合法，随机选择一台NodeManager启动AppMaster
 3、AppMaster根据任务分配向ResourceManager申请Task运行的Container资源
 4、ResourceManager根据资源情况分配对应的Container信息返回给AppMaster
 5、AppMaster根据ResourceManager分配的Container信息，将Container信息分发给对应的NodeManager
 6、NodeManager收到Container信息，启动MapTask和ReduceTask运行
 7、每个Task将自己运行的信息汇报给AppMaster，AppMaster监控每个Task的状态，直到Task结束
 8、AppMaster等到所有Task结束返回运行结果

4. Standalone模式

4.1 什么是Standalone?

Standalone模式，就是Spark实现了一套自己的分布式资源管理和任务调度。类似于MapReduce+Yarn，如下表：

概念YARNSpark Standalone
主节点ResourceManagerMaster
从节点NodeManagerWorker
计算进程ContainerExecutor
调度进程AppMasterDriver
  • 主：Master：管理节点，类比于YARN中的ResourceManager
    • 接受客户端请求：所有程序的提交，都是提交给主节点
    • 管理从节点：通过心跳机制检测所有的从节点的健康状态
    • 资源管理和任务调度：将所有从节点的资源在逻辑上合并为一个整体，将任务分配给不同的从节点
  • 从：Worker：计算节点，类比于YARN中NodeManager
    • 使用自己所在节点的资源运行计算进程Executor：给每个计算进程分配一定的资源
    • 所有Task线程计算任务就运行在Executor进程中
    • 假设每台机器机器：32Core - 64GB
    • 那么Worker的资源由配置决定，例如16Core - 32GB
    • 表示Worker最多能使用这台机器的16Core32GB的资源用于计算
  • 计算进程：Executor：类比于Yarn中的Container，为任务的计算提供资源
  • 调度进程：Driver： 类似于Yarn中的AppMaster，可以对任务进行解析、调度、监控

4.2 Spark执行流程


Spark的核心概念分为两个层面：

  • 资源层面：资源管理
  • 任务层面：任务调度执行

资源层面

Cluster Manager：集群主节点，Standalone模式就是Master，Yarn模式下就是ResourceManager，负责接收客户端请求，对集群资源的管理，从节点管理等。 Worker Node：集群从节点，负责改节点资源管理 功能：负责对整个集群资源的管理。 注意： 资源层面的进程，无论是否有任务提交，这些进程都是不间断运行的。

计算层面

Driver Program：Driver进程，当任务提交时，在集群的主节点启动，负责任务的解析、调度，监控等。 Executor：计算进程，当提交任务时，在集群的从节点启动，每一个Spark程序都至少有1个。 功能：对提交到集群运行的任务进行解析、调度、执行、监控。 注意： 计算层面的进程，只有当任务提交时才有，任务执行完成后，进程被销毁，资源释放。

小结

Spark既能做到资源的管理，也能做到任务的调度，可以不依靠外部其他服务独立运行，完成对数据的统计分析。 因此说Spark是一个统一的数据处理引擎。

5. Yarn模式

为什么要将Spark的程序运行在Yarn上，不运行在自带的Standalone集群上？ 工作中的计算集群大多数情况下只有1套集群，如果Hadoop生态的程序，例如MR、Hive、Sqoop、Oozie等使用Yarn来计算， 而Spark的程序单独用Standalone集群来计算，就导致了一套硬件资源被两套资源管理平台所管理，使用时会导致资源竞争冲突等问题， 不能充分的发挥硬件资源的性能且管理麻烦。 反过来，既然Spark任务提交在Yarn上运行，那还要Standalone集群干嘛呢？ 这就是有没有和用不用的区别。 如果没有，则Spark就高度依赖Yarn。形成了强绑定关系一样，很显然，这样风险太大了。

5.1 什么叫Yarn模式

把Spark程序提交到Yarn上来运行，使用Yarn的分布式资源管理给Spark程序分配资源。 注意： Spark一旦提交给Yarn来运行，就和Standalone模式没有任何关系了。

6.2 deploy-mode

Spark Application提交运行时部署模式Deploy Mode，表示的是Driver Program运行的地方。 要么是提交应用的客户端节点：client，默认就是client，也叫客户端模式。 要么是集群中从节点（Standalone：Worker，YARN：NodeManager）：cluster，也叫集群模式。 问题：这两种模式有什么区别吗？ Cluster和Client模式都是在Yarn平台上运行的，最本质的区别是：Driver程序运行在哪里。 使用场景：

  • Standalone集群下的deploy-mode
    • client模式功能：整体负责实现资源申请、Task的解析、调度和监控结论：Driver在客户端机器上启动。
    • cluster模式功能：整体负责实现资源申请、Task的解析、调度和监控结论：Driver在集群内的某一个节点启动。
  • Yarn集群下的deploy-mode

    • client模式

    • 功能： AppMaster运行在NodeManager上：负责申请资源，启动Executors、反馈结果 Driver运行在客户端机器上，运行在客户端进程内部：负责解析、调度和监控Task

    • cluster模式——

  • AppMaster和Driver合二为一，都运行在集群内部的某个节点上，可以理解为AppMaster就是Driver（包含Driver）。功能：整体负责实现资源申请、Task的解析、调度和监控结论：Driver就是AppMaster，在集群内的某一个节点启动。

常用参数

参数描述
–masterspark://host:port 、mesos://host:port、k8s://https://host:port、local[N]
–deploy-mode提交方式：client、cluster；client在本地客户端启动driver、cluster在集群内部某一节点上启动driver
–class应用程序的主类，运行某个类，用Python写不用管，用于Java/Scala
–name应用程序的名称，等同于代码中setAppName
–jars指定额外的第三方依赖包，例如读写MySQL，需要MySQL的驱动包，用，分割
–files需要放到应用工作目录的文件列表，以，分隔。需要分发到各节点的数据文件
–conf指定一些其他配置–conf key=value， 等同于代码中set方法，分区数
–queue队列的配置，默认就是default，公司中实际项目运行时，一般不会是default队列，队列名随意，建议使用项目名来命名。
–supervise用于保证Driver进程安全，故障以后会自动重启，只能用于Standalone模式的cluster模式
–properties-file加载外部包含键值对的属性文件；如果不指定，就默认读取spark安装目录下的conf/spark-defaults.conf文件中的配置
–driver-memory用于指定Driver进程运行时能够使用的内存大小，默认1g
–driver-cores用于指定Driver进程运行时能够使用CPU的核数，默认1核

–executor-cores每个executor进程所使用的CPU核心数，默认1
