自动推断类型转换

问题1：工作中如果遇到了数据源是半结构化数据或者特殊格式的数据，能否直接使用SparkSQL进行处理？ 不能 SparkCore：适用于结构化或者非结构化的数据的处理 SparkSQL：适用于结构化数据的处理 解决：先用SparkCore将非结构化数据进行清洗转化成结构化数据，然后使用SparkSQL进行统计分析

问题2：如果先用SparkCore，再用SparkSQL，那么怎么将RDD转换成DataFrame？ 自动推断类型转换 设计：将RDD中每条数据转换成Row类型，Spark可以自动将RDD转换成DataFrame

  • RDD + Schema = DataFrame
  • RDD[Row]：Row类型中是包含Schema
# step1: 读取数据
# 用RDD方式进行读取
movie_rdd = spark.sparkContext.textFile("../data/people.txt")

# step2: 处理数据
"""反射方式：将RDD中的元素类型转换为Row类型，Spark可以自动推断转换为DataFrame"""
# a.将str类型的RDD变成Row类型的RDD
movie_rdd_row = ( movie_rdd
    # 先将每个字符串分割，变成列表
    .map(lambda line: re.split("\\s+", line))
    # 将每个列表转换成一条Row类型对象数据
    .map(lambda item: Row(userid=item[0], movieid=item[1], rate=float(item[2]), ts=int(item[3])))
)

"""自动推断：RDD中每条数据必须为Row类型，Spark就可以实现自动推断"""
# b.将RDD转换成DF
movie_df = spark.createDataFrame(movie_rdd_row)

# step3: 保存结果
movie_df.printSchema()
movie_df.show()

自定义Schema转换

  • 步骤
    • 第一步、Create an RDD of tuples or lists from the original RDD
      • RDD中数据类型为元组或列表，比如RDD[list] 或 RDD[tuple]
    • 第二步、Create the schema represented by a StructType
      • 创建Schema，定义列名称和列类型，与第一步中RDD匹配
    • 第三步、Apply the schema to the RDD via createDataFrame method provided by SparkSession.
      • 使用SparkSession组合RDD和Schema，转换为DataFrame
  • 实例
# a.读取数据放入RDD中
move_rdd_str = spark.sparkContext.textFile("../data/u.data")

# step2: 处理数据
# b.转换为DataFrame
"""自定义Schema：构建一个元素或者列表类型的RDD，
自定义一个Schema对象StructType，将RDD和Schema对象合并"""
# 先构建元组类型的RDD
movie_rdd_tuple = ( move_rdd_str
                  # 将一行一个字符串转换成一个列表
                  .map(lambda line: re.split("\\s+", line))
                  # 将一行一个列表转换成一个元组对象
                  .map(lambda item: (item[0], item[1], float(item[2]), int(item[3])))
)

# 自定义一个Schema对象
movie_schema = StructType([
    StructField(name="userid", dataType=StringType(), nullable=True),
    StructField(name="movieid", dataType=StringType(), nullable=True),
    StructField(name="rate", dataType=DoubleType(), nullable=True),
    StructField(name="ts", dataType=LongType(), nullable=True)
])

# 将RDD和Schema合并，转换为DataFrame
movie_df = spark.createDataFrame(movie_rdd_tuple, movie_schema)

# step3: 保存结果
movie_df.printSchema()
movie_df.show()

DSL风格

DSL称之为：领域特定语言。其实就是指DataFrame的特有API，以调用API的方式来处理数据。

#1.选择相应的API

#2.点击API进去看看Parameters和Examples
#2.1 Parameters的类型： 在DSL中一般有三种类型，str（字符串）、Column（对象）、list（列表）。有些API算子不一定三种都有。
而且也没有规律。所以需要用户自己留意。可以参考Examples部分的案例。

SQL关键字同名的API


说明

# 1、选择函数select：选取某些列或者某些函数表达式的值
def select(self, *cols: Union[Column, str]) -> DataFrame

# 2、过滤函数filter/where：设置过滤条件，类似SQL中WHERE语句
def filter(self, condition: Union[Column, str]) -> DataFrame

# 3、分组函数groupBy/rollup/cube：对某些字段分组，在进行聚合统计
def groupBy(self, *cols: Union[Column, str]) -> GroupedData

# 4、聚合函数agg：通常与分组函数连用，使用一些count、max、sum等聚合函数操作
def agg(self, *exprs: Union[Column, Dict[str, str]]) -> DataFrame

# 5、排序函数sort/orderBy：按照某写列的值进行排序（升序ASC或者降序DESC）
def sort(self,
         *cols: Union[str, Column, List[Union[str, Column]]],
ascending: Union[bool, List[bool]] = ...) -> DataFrame

# 6、限制函数limit：获取前几条数据，类似RDD中take函数
def limit(self, num: int) -> DataFrame

# 7、重命名函数withColumnRenamed：将某列的名称重新命名
def withColumnRenamed(self, existing: str, new: str) -> DataFrame

# 8、删除函数drop：删除某些列
def drop(self, cols: Union[Column, str]) -> DataFrame

# 9、增加列函数withColumn：当某列存在时替换值，不存在时添加此列
def withColumn(self, colName: str, col: Column) -> DataFrame

RDD同名的API


函数说明如下：

  • count：统计行数
  • collect：将DataFrame转换成一个数组
  • take：取DataFrame中前N行的数据
  • first：取DataFrame中第一行的数据
  • head：默认取DataFrame中第一行的数据，可以指定返回前N行的数据
  • tail：可以指定返回后N行的数据
  • foreach：对DataFrame中每条数据进行处理，没有返回值
  • foreachPartition：对DataFrame中每个分区数据进行处理，没有返回值
  • distinct：对DataFrame中每条数据进行去重处理
  • union/unionAll：实现两个DataFrame的合并
  • coalesce/repartition：调整DataFrame的分区数
  • cache/persist：对DataFrame进行缓存
  • unpersist：取消DataFrame的缓存
  • columns：返回DataFrame中的所有列名
  • schema：返回DataFrame中Schema的信息
  • rdd：返回DataFrame中的数据放入RDD中
  • printSchema：打印DataFrame的Schema信息

Catalyst优化器

SQL和DSL都能实现SparkSQL开发，那么哪种性能更好？
SQL引擎结构
​
说明
客户端：写代码，提交代码
服务端：处理SQL的地方

  • 解析器：负责校验和解析SQL语句，校验语法、数据库、表、字段类型的合法性
  • 编译器：将SQL元数据信息转换成逻辑计划语法树
  • 优化器：负责对逻辑计划进行优化，选择最优方式执行逻辑计划，并生成物理计划
  • 执行器：负责执行物理计划，实现任务的运行
Hive的元数据存储在MySQL中
MySQL的元数据存储在MySQL中

Catalyst优化器
​
（1）SQL语句首先通过Parser模块被解析为语法树，此棵树称为Unresolved Logical Plan​（SQL语法是否有错误）
（2）Unresolved Logical Plan​通过Analyzer模块借助于数据元数据解析为Logical Plan​（字段，表是否存在）
（3）此时再通过各种基于规则的Optimizer进行深入优化，得到Optimized Logical Plan​（RBO：谓词下推，常量折叠，列值裁剪）
（4）优化后的逻辑执行计划依然是逻辑的，需要将逻辑计划转化为Physical Plan，再根据代价模型cost model，哪个耗时最少，耗内存最小，筛选出代价最小的物理计划，这个过程称之为CBO。
（5）最后依据最优的物理计划，将SQL转换为RDD操作，再划分为DAG，再将DAG的stage的task发送到WorkerNode的Executor的Core上执行。

答案：不论是SQL还是DSL，只要计算的逻辑是一样的，经过优化器，最终的实现也是一样的，所以相同执行逻辑的代码性能上没有区别

读写数据的方式

SparkSQL将所有常用的数据源接口都进行了封装，只需要指定读写的类型和地址就可以实现读写 实现

  • 读数据
    • MapReduce：InputFormat：TextInputFormat【读文件】、DBInputFormat【读MySQL】
    • Spark：DataFrameReader：不同数据来源使用不同对象
  • 写数据
    • MapReduce：OutputFormat：TextOutputFormat【写文件】、DBOutputFormat【写MySQL】
    • Spark：DataFrameWrite：保存数据使用不同对象

输入源

  • ** 类型：text / csv【任意固定分隔符】 / json / orc / parquet / jdbc / table【Hive表】 **
  • ** 语法 **
    • ** 方法：.format【用于指定读取的格式】，.load【用于指定读取文件地址，数据库不用给参数】 **
    • ** 方式一：给定读取数据源的类型和地址 **
spark.read.format("json").load(path)
spark.read.format("csv").load(path)
spark.read.format("parquet").load(path)
  • ** 方式二：直接调用对应数据源类型的方法 **
spark.read.json(path)
spark.read.csv(path)
spark.read.parquet(path)
  • ** 特殊参数：option，用于指定读取时的一些配置选项 **

jdbcDF = spark.read \
    .format("jdbc") \

输出模式

  • 功能：用于保存时指定怎么将数据写入目标数据源
  • 类别：
    Scala/JavaAny LanguageMeaning
    SaveMode.ErrorIfExists (default)“error” or “errorifexists” (default)When saving a DataFrame to a data source, if data already exists, an exception is expected to be thrown.
    SaveMode.Append“append”When saving a DataFrame to a data source, if data/table already exists, contents of the DataFrame are expected to be appended to existing data.
    SaveMode.Overwrite“overwrite”Overwrite mode means that when saving a DataFrame to a data source, if data/table already exists, existing data is expected to be overwritten by the contents of the DataFrame.
    SaveMode.Ignore“ignore”Ignore mode means that when saving a DataFrame to a data source, if data already exists, the save operation is expected not to save the contents of the DataFrame and not to change the existing data. This is similar to a CREATE TABLE IF NOT EXISTS in SQL.

四种模式说明：

append: 追加模式，当数据存在时，继续追加
 overwrite: 覆写模式，当数据存在时，覆写以前数据，存储当前最新数据；
 error/errorifexists: 如果目标存在就报错，默认的模式
 ignore: 忽略，数据存在时不做任何操作

用法：

 df.write.mode(saveMode="append").format("csv").save(path)

整合Hive

Spark读写Hive，也称之为Spark集成Hive。也就是使用Spark来操作Hive。

为什么要集成Hive

Hive底层默认是MR引擎，计算性能特别差，一般用Hive作为数据仓库，使用SparkSQL对Hive中的数据进行计算。

组件功能
HDFS分布式存储，解决原始数据海量存储问题
MapReduce分布式计算，基于写Java代码，开发效率低，计算效率低
HiveMapReduce的SQL客户端，支持通过编写SQL来运行MapReduce程序，开发效率高，但是计算效率低
Spark分布式计算，基于代码和SQL，开发效率高，计算效率高

问题：SparkSQL怎么能访问到Hive中有哪些表，以及如何知道Hive中表对应的HDFS的地址？ 需要将数据仓库的元数据信息告诉Spark。 也就是说，SparkSQL通过访问Hive的Metastore服务获取了Hive元数据，基于元数据提供的地址进行计算。

如何集成Hive

如何集成Hive可以分为两个层面：

  • 前期安装部署时集成
    • 配置hive
# 1、配置hive全局环境变量
vim /etc/profile
# 添加HIVE环境变量
export HIVE_HOME=/export/server/hive
export PATH=$HIVE_HOME/bin:$PATH
# 使配置生效
source  /etc/profile

# 2、启动hive的metastore
nohup hive --service metastore > /tmp/hive-metastore.log &

# 3、启动hiveserver2,用于远程连接

# 2.数据输入
input_df = spark.read.option('header','true').csv("data/people.txt",schema='name string, age int, gender string',sep=';')

# 3.数据处理
# 自定义python函数
def concat_name(name):
    return name + "_charlie"

# 注册函数
# 方式一
concat_name_dsl = spark.udf.register(name="concat_name",f=concat_name,returnType=StringType())
# 方式二 通过pyspark的函数包
concat_name_dsl1 = F.udf(f=concat_name,returnType=StringType())
# 方式三 :通过注解
@F.udf(returnType=StringType())
def concat_name_three(name):
    return name + "_charlie"

SparkSQL分布式引擎

介绍

先来看卡Spark Thriftserver与Hiveserver2、metastore、beeline等的关系：
​
如下图：
​
红色：HiveServer2服务，如果想使用beeline连接Hive，必须启动hiveserver2服务。
绿色：Spark ThriftServer服务，它的出现就是用来代替hiveserver2服务的。
hiveserver2：接收其他远程访问请求，连接远程Hive。远程连接Hive，必须走hiveserver2服务，如beeline、datagrip等。
metastore：Hive服务，metastore服务成功启动，说明Hive运行正常。
beeline：远程连接Hive所用的客户端。
Spark的Thriftserver：类似于Hive的Hiveserver2服务
总结：两者都需要共用metastore服务。

测试步骤

nohup hive --service metastore > /tmp/hive-metastore.log &

注意：

metastore进程会占用【】端口，后续任何服务，如果想连接Hive，就直接找metastore服务即可。

注意不要选取10000端口，因为10000端口通常作为【hiveserver2】进程的端口。比如选用10001

接下来，启动Spark的thriftserver服务：

#1.启动Spark的ThriftServer服务
$SPARK_HOME/sbin/start-thriftserver.sh \
--hiveconf hive.server2.thrift.port=10001 \
--hiveconf hive.server2.thrift.bind.host=node1 \
--master local[*]

最后，启动$SPARK_HOME/bin/beeline客户端，连接Spark的Thriftserver即可：

运行`$SPARK_HOME/bin/beeline`该命令
!connect jdbc:hive2://node1:10001
Enter username for jdbc:hive2://node1:10001: root
Enter password for jdbc:hive2://node1:10001: 123456

注意：

连接数据库需要用户名和密码，就是Linux的用户名和密码。

【了解】如果不输入用户名和密码，则是以匿名用户anonymous登录的，后期有时写表数据时会权限不足。
